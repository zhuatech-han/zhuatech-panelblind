# PanelBlind conventions

Read README and docs before edits. Preserve company attribution, original noncommercial LICENSE and original LOGO / QR assets. Java 21 / Spring Boot / Vue 3 / MySQL 8.4 / Flyway. Keep changes small. Never store credentials or real client product identities in source control.

Approved protocols, roster and cyclic presentation layouts are immutable. Internal raters cannot have edited the protocol or act as custodian/reviewer. Rater membership overrides broad administrative business scope. Expose only their own sheet before and after unblinding; released aggregates are visible to authorized panel members. Keep sample names/ids and submitted scores out of unauthorized detail, JSON, CSV, events and error payloads. Identity keys require a separately assigned custodian or authorized past editor. Do not expose the random generator or identity key through layout proofs.

Required responses need an integer score OR an explicit missing reason. Missing is never zero. Submitted sheets are locked until returned. Accepted or withdrawn sheets remain immutable. Review checks completeness, without changing subjective scores. Final seal needs terminal sheets; successful completion needs at least two accepted sheets. Aborted outcomes remain distinct. Custodian requests unblinding; an independent assigned reviewer approves it. Released data cannot reopen. Only descriptive statistics are implemented: no significance tests, medical use, safety certification or automated product recommendation.

Run formatter, linter, backend unit/integration tests, frontend tests/build, full Docker build without skipping tests, fresh MySQL workflow/scope/migrations, restart and independent backup restoration. Inspect real UI and six screenshot categories, branding, original asset hashes and sensitive data. Inspect Git diff before authorized publication, then verify Public and exact remote SHA/tree/bytes. Clean only this project's temporary test resources.
